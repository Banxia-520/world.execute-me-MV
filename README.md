# world.execute(me); — Procedural Lyrics MV

> 一支把 Mili 的《world.execute(me);》**用代码逐帧计算出来**的程序化歌词 MV。  
> 全片 199 个镜头、12 个章节、3 分 38 秒 98 帧，**没有任何一张手绘素材**：  
> 每一个点、每一根线、每一段文字、每一次碎裂都由代码在运行时生成。

---

## 1. 这是什么

这不是「给歌配插画」，而是**假装有一台计算机正在把歌词本身计算成世界**。

全片的视觉母题是「文字与图形的同构变换」：  
`CIRCUMFERENCE` 的字形会卷成圆周，`TANGENTS` 的字符会生成切线，  
`FRAGMENTS` 的字母会碎成多边形，而 `LOVE` 最终由前面所有数学与数据元素**重构**而成。

画面全部由 **Canvas 2D** 在浏览器里实时绘制：没有视频文件、没有图片素材、没有 3D 模型，  
只有约 1 MB 的 JavaScript 与 1.9 MB 字体。

### 叙事弧

被构造 → 被赋予参数 → 建立世界 → 用数学解释存在 → 模拟感官 → 产生满足 →  
变换身份 → 产生连接 → 达到完整 → 失去 → 孤独 → 擦除碎片 → 发生非法参数 →  
执行 → 重新寻找 → 学会爱 → 发现「自由」和「被困」**可以同时存在**。

## 2. 快速开始

### 环境要求

| 依赖             | 版本      | 必需性    | 说明                                                    |
| -------------- | ------- | ------ | ----------------------------------------------------- |
| **Python**     | 3.10+   | **必需** | 只用来起本地静态服务（`server.py` 仅用标准库，**无需 pip install 任何东西**） |
| **浏览器**        | 任意现代浏览器 | **必需** | Chrome / Edge / Firefox / Safari 均可                   |
| **Node.js**    | 18+     | 可选     | 仅在跑自验脚本时需要；**看 MV 不需要**                               |
| Pillow / numpy | —       | 不需要    | 那是离线渲染器用的，本仓库不含                                       |

### 三步跑起来

```bash
python3 server.py            # 默认端口 8777
# 端口被占用时：
python3 server.py --port 8899
```

**然后浏览器打开：**

```
http://127.0.0.1:8777/index.html
```

> **为什么需要一个服务器？** 页面用了 ES Modules 与 `fonts` API，浏览器对  
> `file://` 协议下的模块加载有安全限制。`server.py` 就是为此存在的——  
> 它只做两件事：托管静态文件、支持音轨的 Range 请求（播放器据此实现拖动定位）。

### 时间轴

| 区间                | 内容                     |
| ----------------- | ---------------------- |
| 0:00 – 0:03       | 片头警示卡（**静音**，倒数 3→2→1） |
| **0:03**          | 正片开始，**音乐同时进入**        |
| 0:03 – 3:34.98    | 正片 199 镜（211.9837s）    |
| 3:34.98 – 3:38.98 | 片尾署名卡（4s）              |
| **3:38.98**       | 总时长 218.9837s          |

> **音轨为什么比正片长？** `media/player_audio.m4a` =  
> `3.0s 前导静音 + 211.9837s 母版 + 4.0s 尾静音`。  
> 把静音直接做进文件，播放器从 0 播放即可，**完全不需要 seek**，  
> 时间轴天然对齐、不可能错位。

### 可选：本地自验

```bash
# 引擎 + 确定性（30 项）
node tools/test_engine.mjs

# 播放器启动 / 片头卡 / 进度条 / 片尾卡（含「音频结束后要走完 4s 尾卡」的回归）
node tools/test_app_boot.mjs

# 逐章自验：时间、seed、绘制数、确定性（12 个章一次跑完）
node tools/check_chapter.mjs ch01 ch02 ch03 ch04 ch05 ch06 ch07 ch08 ch09 ch10 ch11 ch12

# PIL 语义垫片能力测试（第 10–12 章依赖）
node tools/test_pildraw.mjs

# 真实字形栅格诊断（第 10–12 章的粒子字 / 点阵字依赖）
node tools/diag_realraster.mjs

# 端到端：能否真的播到片尾卡
node tools/repro_outro.mjs
```

> 在只有 `web/` 的环境里，`test_engine.mjs` 会显示 **29 通过 0 失败**：  
> 第 30 项是「跨语言 RNG 比对」，需要 Python 侧生成的参考值  
> （通过环境变量 `RNG_EXPECT` 传入）。缺少时它会打印「跳过跨语言比对」而不是失败。  
> **只要「失败」为 0 即正常。**

### 为什么会有四套绘制架构

12 章的原始 Python 实现并非同一风格，JS 侧如实对齐，因此有四条通路：

| 架构                      | 章节    | 上下文形态              | 适配方式                    |
| ----------------------- | ----- | ------------------ | ----------------------- |
| `sNNN(f, t, sc)`        | 01–03 | `Frame`（四个标量坐标）    | 内建                      |
| `sNNN(K, t)`            | 04–06 | `Kit`（点对坐标）        | 内建                      |
| `_sNNN(c, t)`           | 07–09 | 章内 `Canvas` 类      | `kit.js` 的 `Canvas`     |
| `class` + 裸 `ImageDraw` | 10–12 | PIL `ImageDraw` 对象 | `canvas.js` 的 `PilDraw` |

`PilDraw` 是把 PIL 的 `d.line / d.rectangle / d.text / d.ellipse / d.polygon / d.arc`  
语义映射到 Canvas 的垫片。PIL 里「预旋转字形蒙版 + `paste`」的写法，  
在浏览器里改用 Canvas 的 `translate + rotate + fillText` 等价实现。

### 确定性契约

全片最关键的一条不变量：

> **`position = f(time)`。每一帧都是绝对时间的纯函数，不依赖任何跨帧状态。**

配套手段：

- **固定 seed**：每个镜头一个 8 位十六进制 seed，随机数由 `(seed, 系统名, 索引)`  
  经 splitmix64 + mulberry32 派生
- **禁止实时 FFT**：节拍取自 `data/beats.json` 的**预计算网格**，而非运行时分析音频
- **BPM 130 + 相位 0.16**，共 459 个拍点

因此同一 `(镜头, 时间)` 无论渲染多少次、在哪台机器上，都得到**逐字节一致**的画面——  
这也是上一节那些自验脚本能够成立的前提。

> 想自己验证？任选两个时间点，连续调用两次渲染，对比绘制调用序列即可：  
> `node tools/check_chapter.mjs ch07` 会报告每镜的「确定性 OK/FAIL」。

## 4. AI 怎么理解这首歌，Prompt 是怎么做的

### 4.1 对歌曲的理解

《world.execute(me);》表面是一段**程序向人类告白的日志**：一个被构造出来的执行体，  
把自己的存在拆成参数和函数，用 `if / then` 求爱，最后请求被执行。

AI 侧把这层理解提炼成三条可执行的视觉判断：

**① 这是一份「运行时日志」，不是一首情歌。**  
所以全片采用终端语法：`> execute(me)`、`execution complete`、`ERR:42`、  
`if (...) { ... }`、`broadcast:512`，以及四角微信息里的 `seed:` / `node:` / `frame:`。  
**歌词不做底部字幕，而是直接成为画面对象。**

**② 情感进程可以映射成色彩与信息密度曲线。**  
愤怒不靠表情，而靠**错误红铺满屏幕**；结束不靠戏剧化，而靠**把图标为 0、把文字静默**。

| 阶段           | 色彩     | 信息密度  |
| ------------ | ------ | ----- |
| 被构造 / 建立世界   | 冷静蓝、青白 | 克制、稀疏 |
| 生存 / 模拟 / 满足 | 青白     | 越来越复杂 |
| 连接 / 完整      | 情绪紫    | 最密    |
| 失去 / 崩坏      | 红      | 开始失真  |
| 执行           | 白      | 急剧降低  |
| 终章           | 黑白     | 重新极简  |

**③ 「自由」与「被困」是同一个几何事实。**  
这是全片立意所在：第 11 章让立方体的门**真的打开**、亮点**真的飞出去**，  
但镜头随即内翻——观众发现自己站在了盒子**里面**。  
同一个立方体，从外面看是自由，从里面看是牢笼。  
最后一镜 `> _` 的光标与一粒种子亮点，把「执行结束」和「循环即将重启」叠在同一帧上。

### 4.2 Prompt 体系：五层约束，而不是一句描述

这份 Prompt 不是「描述画面让模型画」，而是**给代码生成器写规格**。分五层：

| 层              | 内容                                    | 解决什么              |
| -------------- | ------------------------------------- | ----------------- |
| **总纲**         | 画布 / 调色板 / 字体 / 三层结构 / 镜头继承原则         | 全片视觉语法统一          |
| **镜头级 Prompt** | 199 镜逐镜：展示什么、排版规格、出现顺序、运动方式、技术实现、如何衔接 | 每个镜头可独立实现         |
| **负面 Prompt**  | 全局禁止项                                 | **最容易被忽视、却最决定成败** |
| **实现 Prompt**  | 把视觉规格翻译成代码约束（确定性、纯函数、seed、坐标系）        | 保证可复现             |
| **细节规格**       | 逐镜像素级细节：字号、字距、坐标百分比、缓动曲线、帧数           | 消除歧义              |

### 4.3 关键做法

**① 色彩登记制。**  
调色板只有 10 个登记色，代码**不允许出现新颜色**——所有透明度变化都是「向背景混色」：

```js
// 只允许引用已登记色；透明度 = 与背景混合
const ICE = [234, 247, 255], CYAN = [53, 217, 232], MOODPURPLE = [168, 140, 255];
```

这一条把「AI 生成画面容易花」的问题从根上堵死。

**② 负面 Prompt 比正面描述更重要。**  
明确禁止：大面积霓虹彩虹、俗套赛博朋克、真实人物 / 品牌 / AI 模型身份、  
底部传统字幕、无 seed 的随机粒子。  
没有这一层，模型几乎必然把「计算机 + 爱情 + 数学」做成满屏霓虹。

**③ 时间从节拍网格推导，不靠感觉。**  
BPM 130、起始相位 0.16，459 个拍点预先算好写进 `data/beats.json`。  
镜头内的「脉冲」「闪烁」「错峰」都取 `phase(t, t0, t1)`，  
保证与音乐卡点一致且可复现。

**④ 三层画面结构强制。**  
每一镜都必须有 **主视觉 + 次视觉 + 微信息**：  
主视觉是当前最重要的词或几何对象；次视觉是解释它的数学 / 粒子 / 结构；  
微信息是角落里的极小时间、坐标、节点数。**微信息永远不能喧宾夺主。**

**⑤ 「上一镜必须留一个元素给下一镜」。**  
明确禁止「每句歌词换一张图」。继承物可以是点、线、圆、光标、粒子、文字轮廓、  
轨道或颜色——于是 199 镜连成一条**连续变形**的线，而不是 199 张幻灯片。

**⑥ 文字与图形同构。**  
`CIRCUMFERENCE` 的字形卷成圆周、`TANGENTS` 的字符生成切线、  
`FRAGMENTS` 的字母碎成多边形、`LOVE` 由前面所有数学元素重构。  
这一条让「歌词」不必以字幕形式出现，却能一直在场。


**⑦ 中文只作制作备注，不上屏。**  
英文歌词原文才是成片展示的文字。中文用于制作参考，  
全片**没有任何一镜把中文作为画面元素**。

**⑧ 把「修正」也写进规格。**  
规格不是一次成型的。例如原稿把正片长度写成 `216.97s / 13018 帧`，  
而实测母版只有 `211.9837s / 12719 帧`，长了 4.99 秒——  
第 12 章因此整体重排进 `[205.81, 211.9837]`。  
**规格与实现的偏差要显式记录，而不是悄悄改代码。**

## 附：常见问题

**Q：需要 `npm install` 吗？**  
不需要。没有任何第三方 JS 依赖，也没有 `package.json`。

**Q：能直接双击 `index.html` 打开吗？**  
不能。ES Modules 与字体加载在 `file://` 下有安全限制，请用 `server.py` 起服务。

**Q：端口被占用怎么办？**  
`python server.py --port 8899`，然后访问对应端口。

**Q：为什么片头 3 秒没有声音？**  
那是刻意的：片头卡是警示卡，正片第一帧与音乐**严格同起于 3.0s**。  
前导静音做进了音频文件本身，所以不需要 seek 就能对齐。

**Q：画面是实时画的，性能如何？**  
绝大部分镜头是纯 Canvas 2D 绘制，桌面浏览器轻松满帧。  
第 10–12 章的粒子字/点阵字单帧可达数千次绘制调用，属全片最重的部分。

**Q：能做到逐字节复现吗？**  
能。见上文「确定性契约」——所有随机数来自固定 seed，所有时间来自绝对时间，  
自验脚本会逐镜检查两次绘制的调用序列是否完全一致。
